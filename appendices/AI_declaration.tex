\section{AI Work Declaration}
\label{app:ai_work}

Three AI tools were used in this project, each for a different purpose:
\begin{itemize}[label=\textbullet]
  \item \textbf{Claude (Anthropic)} used for logical and complex tasks:
    troubleshooting, code review, data-processing scripts, planning and
    converting Word documents into \LaTeX{}.
  \item \textbf{GitHub Copilot}, within VS Code, used for autocompletion of
    spelling and citations while writing.
  \item \textbf{Gemini (Google)} used for restructuring language in the report.
\end{itemize}
I used AI as a tool to support my own work, not to replace it.
Every output was reviewed, tested or checked by me before it was
used.

In the project work, AI was used for the following:
\begin{itemize}[label=\textbullet]
  \item \textbf{Troubleshooting.} Diagnosing hardware and firmware problems
    during bring-up and testing, by discussing symptoms and suggesting likely
    causes and checks, which I then carried out on the hardware.
  \item \textbf{Exploring solutions.} Suggesting and comparing alternative
    approaches to design problems. I then made the choice between them, for the reasons given in the report.
  \item \textbf{Code review and improvement.} Restructuring weak or repetitive
    sections of the firmware, checking the code for loopholes and edge cases,
    and adding safety measures such as input limits, time-outs and overload
    handling (Section~5.5.2).
  \item \textbf{Data-comparison scripts.} Setting up Python scripts to
    process and compare the data measured on the OpenStat and the PalmSens4
    (Chapter~6).
  \item \textbf{Planning.} Helping to plan the project schedule
    (Appendix~A) and to break tasks into manageable steps, which improved
    time efficiency.
\end{itemize}

In writing the report, AI was used for the following:
\begin{itemize}[label=\textbullet]
  \item \textbf{Software chapter.} For Chapter~5 (Software Design), Claude
    was given sections of firmware code, from which it drew the flow
    diagrams were drafted. I then checked the diagrams against the code and the behaviour of the device, and corrected them where they did not match.
  \item \textbf{Drafting.} Text in Chapter~6 (Testing and Calibration),
    Chapter~7 (Environmental and Sustainability Analysis), Chapter~8
    (Conclusion and Future Work) and Appendix~B (Graduate Attributes) was
    improved with Claude, which flagged incomplete sentences and
    inconsistencies. The content was reviewed, corrected, edited, and checked against  measured data and the cited sources.
  \item \textbf{Conversion to \LaTeX{}.} Chapter~4 (Hardware Design) was
    written by the student as a rough draft in Word and converted into
    \LaTeX{} with Claude, which also flagged incomplete sentences and
    inconsistencies for the student to resolve.
  \item \textbf{Language editing.} In Chapters~1 to~3, AI was used only to improve structure, clarity and flow, mainly with Gemini.
  \item \textbf{Diagrams.} Drawing figures in \LaTeX{} (TikZ), including the
    software flow diagrams of Chapter~5.
  \item \textbf{\LaTeX{} support.} Finding and fixing compilation errors,
    and checking that all figures, tables, equations and sections are
    correctly referenced.
  \item \textbf{Proofreading.} Checking spelling, with Copilot also
    completing references while writing in VS Code.
\end{itemize}

All AI outputs were verified before use. Firmware changes were compiled, flashed
and run on the OpenStat, and their behaviour was checked against the serial
output. An oscilloscope was used to confirm that the code produced the
correct DPV excitation waveform (Section~6.1). Not all
AI-suggested code worked: parts of the display, web dashboard and SD card
code, and of the range-selection and calibration code, failed on the
hardware and had to be debugged and corrected by me before they
behaved as intended. The layout of the graphical interface and the way the user interacts with the device were designed by me.

AI was not used to generate or alter any measured data. All results and
conclusions in this report are based on measurements made during testing.

\section{Own Work Declaration}
\label{app:own_work}

The following was done by the student:
\begin{itemize}[label=\textbullet]
  \item \textbf{Project definition.} Defining the aim, scope and
    requirements of the project with the supervisor (Chapter~1,
    Tables~4.1 and~4.2).
  \item \textbf{Literature review.} Finding, reading and selecting the
    sources reviewed in Chapter~2.
  \item \textbf{Hardware design.} Selecting the components, designing the
    schematic and PCB layout in KiCad, ordering the board, and assembling
    and bringing up the prototype (Chapter~4).
  \item \textbf{Firmware.} Writing the firmware, designing the code structure including, current measurement and range
    selection, and making the design decisions behind them (Chapter~5).
  \item \textbf{User interface.} Designing the layout of the onboard screens
    and web dashboard, and how the user interacts with the device.
  \item \textbf{Testing and calibration.} Carrying out all
    measurements, including the waveform, resistor calibration, Randles
    circuit, salt and ferricyanide tests, preparing the test solutions and
    operating the PalmSens4 (Chapter~6).
  \item \textbf{Analysis and conclusions.} Interpreting the results and
    drawing the conclusions of Chapters~6 to~8.
\end{itemize}
